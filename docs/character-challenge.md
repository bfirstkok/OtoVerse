# Anime character letter challenge

Entry: Home → ท้าชื่อตัวละคร A–Z. Two local players or two authenticated online players. Online create provides a 12-character invite code; joining starts the game. Each player starts with two hearts. A–Z is drawn every turn; turns alternate after correct and incorrect answers. Empty submission forfeits one heart. Zero hearts ends the game. Character reuse loses one heart.

Exact normalized full names and catalog aliases are accepted; case, punctuation and accents are ignored. MAL comma-separated family/given names also accept reversed order. Partial names are not automatically accepted. A lazy-loaded snapshot of 1,899 existing characters supplies images, anime titles and music; unknown names use Jikan v4 character search and anime appearances. API errors leave the turn and hearts unchanged. Jikan is an external dependency with rate limits; only the first 25 search results are considered. Catalog snapshot is functions/character-catalog.json, derived from public/animeData.json.

Correct answers reveal for 6 seconds, with an optional YouTube player mounted only during that interval. Music defaults on; browsers may require clicking Play. Music is available when the anime has a matching song in the catalog; unknown anime show a missing-song message. Images and YouTube availability depend on the external providers.

Online state lives in characterRooms, separate from song rooms. The characterChallenge callable in asia-southeast1 authenticates membership, checks active player/revision/reveal deadline before lookup, then rechecks in a Firestore transaction. Clients may read only rooms they belong to and cannot write game state. The server selects letters and validates characters; clients cannot submit character metadata or scores. Explicit Back/Leave closes the room. Abrupt browser closure does not close a room automatically; players can leave and create another room. Rejoining by invite restores an existing member session.

No deployment was performed. Online use requires a coordinated future release of the callable, Firestore rules, and frontend. Existing production rules/functions will not support this new mode until released. No existing song-room API or rules were changed.

Validation: npm run test:characters (11 engine and callable tests; callable tests use an in-memory Firestore substitute); npm run build; node --check functions/character-challenge.js. Live authenticated two-browser testing and security-rule emulator testing remain required before release (Java/emulator runtime unavailable here). Manual checks: local alternating answers and hearts, reveal/audio stopping, duplicate rejection, winner, replay; online host/join, waiting opponent, double submit, leave, reconnection, service failure.
